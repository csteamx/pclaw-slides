能力 · 质量与协作

质量靠流程，协作靠一份共享的上下文

质量AI 审查

「必须修改」只限需求没完成、bug、安全、丢数据、构建失败；其余是建议。复审只核对上一轮，不会无限审。

质量质量门禁

挂在状态流上：最近一次审查「可以提交」、之后没再改代码，工作项才能流转到「已完成」。

质量用例与 PR

AI 生成用例写进 TestHub、本机执行后回填；PR 合并后 webhook 把工作项自动走到完成。

协作领取即开工

只有负责人能让 AI 干活；没人领的工作项，开工时自动指派给自己并改成「进行中」。

协作约定统一注入

分支名规则、提交信息模板、项目规则自动带进上下文 —— 每个人的 AI 守同一套规矩。

协作完成提醒

AI 跑完，在 PingCode 任意页面弹卡片，还有系统桌面通知；Claude Code、Codex、Cursor 各用各的。

⏱ 1 分钟（AI 编码时讲）→ 讲完回浏览器看结果

有了 AI，质量更不能靠自觉：审查有明确标准，结论接上 PingCode 的状态流校验器，没过审查流转不到「已完成」；PR 合并后自动完成。

协作的关键：上下文是共享的，AI 是各自的。领取规则、统一约定、完成提醒，让多人并行不打架。

技术 · 架构

浏览器直连本机，AI 在你自己的电脑上跑

4个 AI 编码 CLI 7个 PingCode 功能入口 4个子产品打通 + GitHub

⏱ 1 分钟（累计 13:00）

技术上一句话：浏览器直连本机，AI 在你自己的电脑上跑。

配对：宿主页面向平台换一个 5 分钟的 NIT 令牌，带着它调本机的 /pair，cli 用平台公开的 JWKS 验签，用户零配置。

运行：页签 iframe 直接 fetch 本机，用 SSE 逐字读，真流式，不经过平台。

边界：本机 cli 不持有任何平台凭据，归档由页面经 resolver 写进 CES；代码和密钥不出本机。

附录 · 技术难点

啃下来的几块硬骨头

01iframe 怎么连本机

ws:// 会被 CSP 拦下；实测 fetch + SSE 直连可通，做到逐字流式。浏览器真拦了也不怕：自动降级为宿主代发 + 轮询。

02身份从哪来

不让用户贴令牌。宿主向平台换 5 分钟的 NIT，本机用 JWKS 验签、按 jti 去重；一个 cli 只绑一个账号。

03四个 CLI，一个通道

stream-json、JSON-RPC…… 格式各不相同，统一成思考、逐字、工具调用、轮次四类事件，并支持跨轮续接。

04只读要真只读

规划、分析、开发方案不能改代码：Claude Code / CodeBuddy 用 plan 模式，Codex 用只读沙箱，Cursor 用 ask 模式。

05网络这一关

Claude Code / Codex 要代理：按设置 → 环境变量 → 系统代理的顺序找，并真连一下端口；找不到就明说，不让它卡死。

06平台的坑先踩

远端用 npm 装依赖、不认 workspace: 协议，失败还没有日志 —— 协议改为内联副本 + 构建前校验，宁可本地失败。

⏱ 备用：被问到技术细节时

挑几个难点讲（按时间选讲 2~3 个）：

01 iframe 访问本机：WebSocket 被 CSP 拦，实测 fetch + SSE 是通的，就改成 SSE；还做了降级通道。

02 身份：不让用户贴令牌，用平台签发的 NIT，零配置。

04 只读：规划和分析阶段要保证 AI 不动代码，四个 CLI 各自对上了只读模式。
