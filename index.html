问题 · 根因

AI 让「写」变快了，「记」却没跟上

需求
在脑子里

对话与决策

代码

代码只说明了「是什么」，「为什么」留在对话里 —— 然后蒸发了。我们叫它上下文蒸发。

功能无脑堆叠不知道边界，只能往上加
架构悄悄漂移每轮对话各做各的设计
交接全靠口述没有记录，只有记忆
多人各说各话每个人的 AI 互不相识

我们把这个问题叫做「上下文蒸发」。

需求在脑子里，没写下来；决策在对话里，窗口一关就没了；最后只剩下代码。代码只能告诉你「是什么」，「为什么」已经蒸发了。

后果（点出）：功能无脑堆叠、架构悄悄漂移、交接全靠口述；多人协作更糟 —— 每个人的 AI 互不相识，各说各话。

能力 · 工作项

一个工作项，五步走完

⓪开发方案

只读分析本地代码：需求理解、实现方案、步骤、风险、工作量

①编码

按方案写代码，逐字流式输出，每轮列出改动的文件

②测试用例

按需求和改动生成用例写进 TestHub；还能在本机逐条执行、回填

③AI 审查

另起审查会话，「必须修改」和「建议修改」分开，复审只核对上一轮

④提交 PR

按团队约定建分支、提交、推送、建 PR，并自动总结归档

这是开发者每天待的地方：工作项详情里的「AI 助手」页签。

顶上选 CLI、模型、推理强度；下面那条是自动带入的上下文：工作项、所属迭代、来源需求、项目约定。

五步：开发方案、编码、测试用例、AI 审查、提交 PR。每一步都在时间线上留下记录，关掉页签再打开，停在原来那一步。

（如在现场编码：差不多该回浏览器看看 AI 写完没有。）

能力 · 质量

质量不靠自觉，靠流程

AI 审查不会无限审下去

「必须修改」只限需求没完成、会出错的 bug、安全、丢数据、构建或测试失败；其余都是建议，不挡提交。第二轮起只复核上一轮。

质量门禁状态流校验器

挂在「进行中 → 已完成」上：最近一次审查「可以提交」、且之后没再改代码，才放行。

测试用例TestHub

AI 按需求和改动设计用例，自动归到需求所在模块；在本机逐条执行，人确认后回填测试计划。

PR 合并即完成GitHub webhook

从 PR 标题认出工作项编号，沿状态流走到「已完成」并留评论；可要求合并时也要过门禁。

有了 AI，质量更不能靠自觉。

审查有明确标准，「必须修改」只限几类严重问题，复审只核对上一轮 —— 不会「审了又改、改了又审」没完没了。

审查结论接上 PingCode 的状态流校验器：没过审查，工作项流转不到「已完成」。

用例写进 TestHub、AI 本机执行后回填；PR 合并后 webhook 自动把工作项走到完成。

能力 · 沉淀

每一次对话，最后都变成团队的知识

工作项对话归档

每段会话由同一个 CLI 写总结，存进 PingCode；提交 PR 后自动归档，打开工作项就能回看。

WikiAI 研发纪要

总结 + 改动文件 + 分支与 PR，一键发布并关联工作项；同一会话再发布只更新正文。

迭代AI 迭代总结

健康度、进度、风险与建议，附上各工作项的纪要；纪要部分不依赖本机，项目经理也能发。

任意文档AI 研发记录

Wiki 文档宏：在设计文档里插入某次研发的总结快照，点编号直达工作项。

重点来了：沉淀。

四层：每段对话由同一个 CLI 写总结，提 PR 后自动归档；一键发布成 Wiki 的「AI 研发纪要」；迭代结束出 AI 迭代总结；还能在任何 Wiki 文档里插入某次研发的记录。

右边是「名单管理」那一篇真实的纪要：总结、改动文件、分支和 PR 都在。

技术 · 架构

浏览器直连本机，AI 在你自己的电脑上跑

@pclaw/cli本机网关 · 已发布到 npm @pclaw/sdk协议契约 · 双方共用 @pclaw/appNexus 应用 · 10 个扩展点

技术上一句话：浏览器直连本机，AI 在你自己的电脑上跑。

配对：宿主页面向平台换一个 5 分钟的 NIT 令牌，带着它调本机的 /pair，cli 用平台公开的 JWKS 验签，用户零配置。

运行：页签 iframe 直接 fetch 本机，用 SSE 逐字读，真流式，不经过平台。

边界：本机 cli 不持有任何平台凭据，归档由页面经 resolver 写进 CES；代码和密钥不出本机。

啃下来的几块硬骨头

01iframe 怎么连本机

ws:// 会被 CSP 拦下；实测 fetch + SSE 直连可通，做到逐字流式。浏览器真拦了也不怕：自动降级为宿主代发 + 轮询。

02身份从哪来

不让用户贴令牌。宿主向平台换 5 分钟的 NIT，本机用 JWKS 验签、按 jti 去重；一个 cli 只绑一个账号。

03四个 CLI，一个通道

stream-json、JSON-RPC…… 格式各不相同，统一成思考、逐字、工具调用、轮次四类事件，并支持跨轮续接。

04只读要真只读

规划、分析、开发方案不能改代码：Claude Code / CodeBuddy 用 plan 模式，Codex 用只读沙箱，Cursor 用 ask 模式。

05网络这一关

Claude Code / Codex 要代理：按设置 → 环境变量 → 系统代理的顺序找，并真连一下端口；找不到就明说，不让它卡死。

06平台的坑先踩

远端用 npm 装依赖、不认 workspace: 协议，失败还没有日志 —— 协议改为内联副本 + 构建前校验，宁可本地失败。

挑几个难点讲（按时间选讲 2~3 个）：

01 iframe 访问本机：WebSocket 被 CSP 拦，实测 fetch + SSE 是通的，就改成 SSE；还做了降级通道。

02 身份：不让用户贴令牌，用平台签发的 NIT，零配置。

04 只读：规划和分析阶段要保证 AI 不动代码，四个 CLI 各自对上了只读模式。
